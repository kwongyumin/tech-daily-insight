# DeFi(탈중앙화 금융) 핵심 프로토콜과 작동 원리

## 개요

DeFi(Decentralized Finance)는 전통적인 금융 중개기관 없이 블록체인 위에서 금융 서비스를 제공하는 생태계다. 은행, 거래소, 보험사 등의 역할을 스마트 컨트랙트가 대체하며, 누구나 인터넷과 지갑만 있으면 접근 가능하다.

2024년 기준 DeFi TVL(Total Value Locked)은 수천억 달러에 달하며, Uniswap·Aave·Compound·Curve 등이 핵심 인프라를 구성하고 있다. 백엔드 개발자 입장에서 DeFi는 단순한 블록체인 응용이 아니라 **분산 상태 머신 위에서 동작하는 금융 로직 설계**라는 점에서 매우 흥미로운 도메인이다.

이 글에서는 DeFi의 핵심 프로토콜—AMM, 대출 프로토콜, Yield Farming—의 작동 원리를 파악하고, Solidity 예제 코드와 함께 실무 관점에서 트레이드오프를 분석한다.

---

## 핵심 개념

### 1. AMM (Automated Market Maker)

전통 거래소는 오더북(Order Book) 방식으로 매수·매도 주문을 매칭한다. AMM은 이 매칭 과정을 **수학 공식**으로 대체한다.

Uniswap v2의 핵심 공식은 **Constant Product Formula**다.

```
x * y = k
```

- `x`: 토큰 A의 풀 보유량
- `y`: 토큰 B의 풀 보유량
- `k`: 상수 (유동성 크기)

사용자가 토큰 A를 넣으면 x가 증가하고, k를 유지하기 위해 y가 감소한다. 즉 토큰 B를 받게 된다. 이 단순한 공식이 **가격 발견, 슬리피지, 유동성 제공자 수익** 모두를 결정한다.

**Uniswap v3**는 여기서 한 발 나아가 **집중 유동성(Concentrated Liquidity)**을 도입했다. LP(Liquidity Provider)가 특정 가격 범위에만 유동성을 공급할 수 있어 자본 효율이 극적으로 향상됐다.

### 2. 대출 프로토콜 (Lending Protocol)

Aave, Compound는 **과담보(Over-collateralized) 대출** 모델을 사용한다.

- 사용자가 ETH 100달러를 담보로 맡기면 USDC 75달러를 빌릴 수 있다(LTV 75%)
- 담보 가치가 하락해 청산 임계값(Liquidation Threshold)을 넘으면 **청산(Liquidation)** 발생
- 청산인은 담보 일부를 할인된 가격에 구매하고 부채를 상환하는 **청산 보상(Liquidation Bonus)**을 받는다

금리는 **이자율 모델(Interest Rate Model)**에 의해 동적으로 결정된다. 자금 사용률(Utilization Rate)이 높을수록 대출 이자율이 오른다.

```
Utilization = Total Borrowed / Total Supplied
Borrow Rate = Base Rate + (Utilization * Slope)
```

### 3. Yield Farming & 유동성 채굴

사용자가 프로토콜에 유동성을 공급하고 **거버넌스 토큰 등 추가 보상**을 받는 메커니즘이다. 연 수익률을 APY(Annual Percentage Yield)로 표현하며, 복리 계산까지 포함한다.

## 실전 예제

### 간단한 AMM 구현 (Solidity)

아래는 Uniswap v2의 Constant Product AMM을 단순화한 구현이다.

```solidity
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.20;

import "@openzeppelin/contracts/token/ERC20/IERC20.sol";
import "@openzeppelin/contracts/token/ERC20/ERC20.sol";

contract SimpleAMM is ERC20 {
    IERC20 public immutable tokenA;
    IERC20 public immutable tokenB;

    uint256 public reserveA;
    uint256 public reserveB;

    uint256 private constant FEE_NUMERATOR = 997;   // 0.3% fee
    uint256 private constant FEE_DENOMINATOR = 1000;

    event Swap(address indexed user, address tokenIn, uint256 amountIn, uint256 amountOut);
    event AddLiquidity(address indexed provider, uint256 amountA, uint256 amountB, uint256 lpTokens);

    constructor(address _tokenA, address _tokenB) ERC20("LP Token", "LP") {
        tokenA = IERC20(_tokenA);
        tokenB = IERC20(_tokenB);
    }

    /// @notice 유동성 공급 - LP 토큰 발행
    function addLiquidity(uint256 amountA, uint256 amountB) external returns (uint256 lpTokens) {
        tokenA.transferFrom(msg.sender, address(this), amountA);
        tokenB.transferFrom(msg.sender, address(this), amountB);

        if (totalSupply() == 0) {
            // 최초 유동성 공급: 기하평균으로 LP 토큰 산정
            lpTokens = sqrt(amountA * amountB);
        } else {
            // 기존 비율 유지: 작은 쪽 기준
            lpTokens = min(
                (amountA * totalSupply()) / reserveA,
                (amountB * totalSupply()) / reserveB
            );
        }

        require(lpTokens > 0, "Insufficient liquidity minted");
        _mint(msg.sender, lpTokens);

        reserveA += amountA;
        reserveB += amountB;

        emit AddLiquidity(msg.sender, amountA, amountB, lpTokens);
    }

    /// @notice 토큰 A → 토큰 B 스왑
    function swapAforB(uint256 amountAIn) external returns (uint256 amountBOut) {
        require(amountAIn > 0, "Amount must be > 0");

        // 수수료 적용 후 실제 투입량 계산
        uint256 amountAInWithFee = amountAIn * FEE_NUMERATOR;

        // x * y = k 공식으로 출력량 계산
        // amountOut = (amountInWithFee * reserveOut) / (reserveIn * 1000 + amountInWithFee)
        amountBOut = (amountAInWithFee * reserveB) / 
                     (reserveA * FEE_DENOMINATOR + amountAInWithFee);

        require(amountBOut > 0 && amountBOut < reserveB, "Insufficient output");

        tokenA.transferFrom(msg.sender, address(this), amountAIn);
        tokenB.transfer(msg.sender, amountBOut);

        reserveA += amountAIn;
        reserveB -= amountBOut;

        // 불변식 검증: k가 유지 혹은 증가해야 함
        assert(reserveA * reserveB >= (reserveA - amountAIn) * (reserveB + amountBOut));

        emit Swap(msg.sender, address(tokenA), amountAIn, amountBOut);
    }

    /// @notice LP 토큰 소각 → 유동성 회수
    function removeLiquidity(uint256 lpTokens) external returns (uint256 amountA, uint256 amountB) {
        require(lpTokens > 0, "Amount must be > 0");

        uint256 supply = totalSupply();
        amountA = (lpTokens * reserveA) / supply;
        amountB = (lpTokens * reserveB) / supply;

        _burn(msg.sender, lpTokens);

        reserveA -= amountA;
        reserveB -= amountB;

        tokenA.transfer(msg.sender, amountA);
        tokenB.transfer(msg.sender, amountB);
    }

    function sqrt(uint256 y) internal pure returns (uint256 z) {
        if (y > 3) {
            z = y;
            uint256 x = y / 2 + 1;
            while (x < z) { z = x; x = (y / x + x) / 2; }
        } else if (y != 0) { z = 1; }
    }

    function min(uint256 a, uint256 b) internal pure returns (uint256) {
        return a < b ? a : b;
    }
}
```

### 이자율 모델 구현 (Solidity)

Compound/Aave 스타일의 Jump Rate Model이다.

```solidity
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.20;

/// @title Jump Rate Interest Model
/// @notice Utilization이 Kink를 넘으면 금리가 급격히 상승
contract JumpRateModel {
    uint256 public constant SCALE = 1e18;

    uint256 public baseRate;       // 기본 금리 (연율, 1e18 = 100%)
    uint256 public multiplier;     // Kink 이전 기울기
    uint256 public jumpMultiplier; // Kink 이후 기울기
    uint256 public kink;           // 임계 사용률 (예: 0.8e18 = 80%)

    constructor(
        uint256 _baseRate,
        uint256 _multiplier,
        uint256 _jumpMultiplier,
        uint256 _kink
    ) {
        baseRate = _baseRate;
        multiplier = _multiplier;
        jumpMultiplier = _jumpMultiplier;
        kink = _kink;
    }

    /// @notice 사용률 계산
    function utilizationRate(
        uint256 cash,
        uint256 borrows,
        uint256 reserves
    ) public pure returns (uint256) {
        if (borrows == 0) return 0;
        return (borrows * SCALE) / (cash + borrows - reserves);
    }

    /// @notice 대출 이자율 계산 (블록당)
    function getBorrowRate(
        uint256 cash,
        uint256 borrows,
        uint256 reserves
    ) public view returns (uint256) {
        uint256 util = utilizationRate(cash, borrows, reserves);

        if (util <= kink) {
            // 정상 구간: baseRate + util * multiplier
            return baseRate + (util * multiplier) / SCALE;
        } else {
            // Jump 구간: kink까지의 금리 + 초과분 * jumpMultiplier
            uint256 normalRate = baseRate + (kink * multiplier) / SCALE;
            uint256 excessUtil = util - kink;
            return normalRate + (excessUtil * jumpMultiplier) / SCALE;
        }
    }
}
```

### Web3.js로 풀 상태 조회

프론트엔드 혹은 백엔드 서비스에서 풀 데이터를 읽어오는 예제다.

```javascript
const { ethers } = require("ethers");

const UNISWAP_V2_PAIR_ABI = [
  "function getReserves() external view returns (uint112 reserve0, uint112 reserve1, uint32 blockTimestampLast)",
  "function token0() external view returns (address)",
  "function token1() external view returns (address)",
];

async function getPoolInfo(pairAddress) {
  const provider = new ethers.JsonRpcProvider(process.env.RPC_URL);
  const pair = new ethers.Contract(pairAddress, UNISWAP_V2_PAIR_ABI, provider);

  const [reserves, token0, token1] = await Promise.all([
    pair.getReserves(),
    pair.token0(),
    pair.token1(),
  ]);

  const reserve0 = ethers.formatUnits(reserves.reserve0, 18);
  const reserve1 = ethers.formatUnits(reserves.reserve1, 6); // USDC는 6 decimals

  // 현재 가격 계산 (token0 기준)
  const price = Number(reserve1) / Number(reserve0);

  // 슬리피지 계산: 1 ETH 스왑 시 예상 출력
  const amountIn = 1;
  const amountOut = (amountIn * Number(reserve1)) / (Number(reserve0) + amountIn);
  const priceImpact = ((price - amountOut) / price) * 100;

  return {
    token0,
    token1,
    reserve0,
    reserve1,
    currentPrice: price.toFixed(2),
    priceImpactFor1ETH: `${priceImpact.toFixed(4)}%`,
  };
}

// 실행 예시
getPoolInfo("0xB4e16d0168e52d35CaCD2c6185b44281Ec28C9Dc") // ETH/USDC Pair
  .then(console.log)
  .catch(console.error);
```

## 주의사항 및 트레이드오프

### 1. 임퍼머넌트 로스 (Impermanent Loss)

AMM에서 LP가 가장 많이 간과하는 리스크다. 두 토큰의 가격 비율이 변하면 LP는 단순 보유 대비 손실을 본다.

```
IL = 2√P / (1+P) - 1  (P = 가격 변화 배수)
```

가격이 2배 오르면 IL은 약 -5.7%, 4배면 약 -20%다. 거래 수수료 수익이 IL을 초과해야 LP가 수익을 낸다.

### 2. 플래시 론 공격 (Flash Loan Attack)

담보 없이 대규모 자금을 한 트랜잭션 내에서 빌리고 갚을 수 있는 플래시 론은 가격 오라클 조작에 악용된다. 해결책으로는 **TWAP(Time-Weighted Average Price) 오라클** 사용, **Chainlink 오라클** 연동, **재진입 방지 (ReentrancyGuard)** 패턴 적용이 있다.

```solidity
// 잘못된 예: 현재 블록 spot price 사용 → 조작 가능
uint256 price = reserveB / reserveA;

// 올바른 예: TWAP 사용
uint256 price = UniswapV2OracleLibrary.currentCumulativePrices(...);
```

### 3. 가스 최적화

온체인 로직은 모든 연산이 가스 비용으로 연결된다. 루프 내 storage 읽기 최소화, `uint256` 대신 적절한 타입 패킹, `view`/`pure` 함수 분리, 이벤트를 통한 데이터 저장 최소화가 핵심이다.

### 4. 청산 봇 경쟁과 MEV

청산 기회가 발생하면 수십 개의 봇이 동시에 경쟁한다. **MEV(Maximal Extractable Value)**를 노리는 봇들은 샌드위치 공격으로 일반 사용자의 스왑에 슬리피지 피해를 준다. Flashbots의 `mev-boost`나 `Cowswap` 같은 MEV 보호 솔루션 활용을 고려해야 한다.

### 5. 스마트 컨트랙트 보안

DeFi는 버그 하나가 수천억 원 손실로 이어진다. 배포 전 **Slither**, **Echidna** 등 정적 분석 도구와 퍼징 테스트를 반드시 수행하고, **Trail of Bits**, **OpenZeppelin** 같은 전문 기관의 감사를 받아야 한다.

## 정리

| 프로토콜 | 핵심 메커니즘 | 주요 리스크 |
|----------|--------------|------------|
| AMM (Uniswap) | Constant Product x·y=k | 임퍼머넌트 로스, 슬리피지 |
| 대출 (Aave/Compound) | 과담보 + 동적 이자율 모델 | 청산 리스크, 오라클 조작 |
| Yield Farming | 유동성 마이닝 + 거버넌스 토큰 | 토큰 인플레이션, Rug Pull |

DeFi 개발은 일반 백엔드 개발과 근본적으로 다른 제약을 갖는다. **코드는 곧 법이고, 배포 후 수정이 어려우며, 모든 상태가 공개된다**. 이 세 가지 특성을 항상 염두에 두고 설계해야 한다.

실무 적용 시에는 검증된 OpenZeppelin 라이브러리를 최대한 활용하고, 핵심 수학 공식의 오버플로우/언더플로우 케이스를 철저히 테스트하며, 업그레이드 가능한 Proxy 패턴(UUPS, Transparent Proxy)을 통해 비상 시 대응 경로를 확보하는 것이 중요하다.

DeFi는 여전히 빠르게 진화하는 영역이다. Uniswap v4의 Hook 아키텍처, EigenLayer의 리스테이킹, 인텐트 기반 아키텍처(EIP-7521) 등 새로운 패러다임이 계속 등장하고 있다. 원리를 깊이 이해한 개발자만이 이 변화에 빠르게 적응할 수 있다.
