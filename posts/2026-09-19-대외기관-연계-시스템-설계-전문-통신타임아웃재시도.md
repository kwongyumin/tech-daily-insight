# 대외기관 연계 시스템 설계: 전문 통신·타임아웃·재시도

## 개요

금융권, 공공기관, 통신사 등과 연계되는 시스템을 개발하다 보면 "대외기관 연계"라는 특수한 영역에 맞닥뜨리게 된다. 일반적인 REST API 호출과는 달리, 대외기관 연계는 **고정 길이 전문(電文, Message Format)** 기반의 TCP 소켓 통신, 엄격한 타임아웃 정책, 그리고 재시도 전략의 복잡성이 맞물려 있다.

이 글에서는 대외기관 연계 시스템을 설계할 때 반드시 고려해야 할 세 가지 축인 전문 통신 구조, 타임아웃 전략, 재시도 설계를 실무 코드와 함께 다룬다. 이미 HTTP 기반 서비스를 운영해본 경험이 있다면, 이 글이 소켓 기반 레거시 연계의 세계를 이해하는 데 도움이 될 것이다.

## 핵심 개념

### 1. 전문(電文) 통신이란?

대외기관 연계에서 "전문"이란 미리 약속된 고정 바이트 구조를 가진 메시지 포맷이다. JSON이나 XML처럼 자기 서술적(self-descriptive)이지 않고, **헤더(공통부) + 바디(업무부)** 구조로 구성되며 각 필드의 위치와 길이가 명세서에 고정되어 있다.

```
[전문 구조 예시]
+------------------+------------------+------------------+
|  공통 헤더 (64B)  |  업무 헤더 (32B)  |  데이터부 (가변)  |
+------------------+------------------+------------------+

공통 헤더:
- 전문길이     : 4byte
- 기관코드     : 8byte
- 업무코드     : 4byte
- 전문일련번호  : 12byte
- 응답코드     : 4byte
- ...
```

이 구조 때문에 직렬화/역직렬화 로직이 복잡해지고, 인코딩(EUC-KR vs UTF-8) 문제까지 더해지면 버그의 온상이 된다.

### 2. TCP 소켓 연결 방식

대외기관 연계는 크게 두 가지 방식으로 이루어진다.

- **Short Connection**: 요청마다 TCP 연결을 맺고 끊는 방식. 구현이 단순하지만 연결 오버헤드가 크다.
- **Long Connection (Keep-Alive)**: 커넥션 풀을 유지하며 재사용하는 방식. 성능이 좋지만 연결 상태 관리가 복잡하다.

대부분의 금융/공공 연계는 Long Connection + 커넥션 풀 방식을 선택하는데, 이 경우 **Stale Connection** 감지와 **Heartbeat** 처리가 필수다.

### 3. 타임아웃의 종류

타임아웃은 단순히 "몇 초"를 설정하는 문제가 아니다. 아래 세 가지를 각각 구분해야 한다.

| 타임아웃 종류 | 설명 |
|---|---|
| Connect Timeout | TCP 연결 수립까지 허용 시간 |
| Read Timeout | 연결 후 응답 데이터 수신까지 허용 시간 |
| Write Timeout | 요청 데이터 전송 완료까지 허용 시간 |

대외기관 특성상 Read Timeout이 가장 중요하다. 기관 내부 처리 지연이 발생할 때 우리 시스템의 스레드가 무한정 블로킹되는 것을 막아야 한다.

## 실전 예제

### 전문 직렬화/역직렬화

Java에서 고정 길이 전문을 다루는 기본 구조를 살펴보자.

```java
public class MessageFrame {
    // 전문 헤더 상수
    private static final int HEADER_LENGTH = 64;
    private static final Charset CHARSET = Charset.forName("EUC-KR");

    private String messageLength;   // 4자리
    private String institutionCode; // 8자리
    private String businessCode;    // 4자리
    private String serialNumber;    // 12자리
    private String responseCode;    // 4자리

    public byte[] serialize(String body) {
        byte[] bodyBytes = body.getBytes(CHARSET);
        int totalLength = HEADER_LENGTH + bodyBytes.length;

        ByteBuffer buffer = ByteBuffer.allocate(totalLength);

        // 헤더 직렬화: 각 필드를 고정 길이로 패딩
        buffer.put(padLeft(String.valueOf(totalLength), 4).getBytes(CHARSET));
        buffer.put(padRight(institutionCode, 8).getBytes(CHARSET));
        buffer.put(padRight(businessCode, 4).getBytes(CHARSET));
        buffer.put(padLeft(serialNumber, 12).getBytes(CHARSET));
        buffer.put(padRight(responseCode, 4).getBytes(CHARSET));
        // ... 나머지 헤더 필드
        buffer.put(new byte[HEADER_LENGTH - buffer.position()]); // 패딩

        buffer.put(bodyBytes);
        return buffer.array();
    }

    public static MessageFrame deserialize(byte[] data) {
        ByteBuffer buffer = ByteBuffer.wrap(data);
        MessageFrame frame = new MessageFrame();

        byte[] lenBytes = new byte[4];
        buffer.get(lenBytes);
        frame.messageLength = new String(lenBytes, CHARSET).trim();

        // ... 각 필드 파싱
        return frame;
    }

    private String padLeft(String value, int length) {
        return String.format("%" + length + "s", value).replace(' ', '0');
    }

    private String padRight(String value, int length) {
        return String.format("%-" + length + "s", value);
    }
}
```

### 커넥션 풀과 타임아웃 설정

Apache Commons Pool2를 활용한 TCP 소켓 커넥션 풀 구현이다.

```java
@Configuration
public class SocketPoolConfig {

    @Bean
    public GenericObjectPool<Socket> socketPool(SocketFactory socketFactory) {
        GenericObjectPoolConfig<Socket> config = new GenericObjectPoolConfig<>();
        config.setMaxTotal(20);          // 최대 커넥션 수
        config.setMaxIdle(10);           // 최대 유휴 커넥션 수
        config.setMinIdle(3);            // 최소 유휴 커넥션 수
        config.setMaxWait(Duration.ofSeconds(3)); // 풀에서 대기 최대 시간
        config.setTestOnBorrow(true);    // 빌릴 때 연결 유효성 검사
        config.setTestWhileIdle(true);   // 유휴 상태에서도 주기적 검사
        return new GenericObjectPool<>(socketFactory, config);
    }
}

public class SocketFactory extends BasePooledObjectFactory<Socket> {

    private final String host;
    private final int port;

    @Override
    public Socket create() throws Exception {
        Socket socket = new Socket();
        socket.connect(
            new InetSocketAddress(host, port),
            3000  // Connect Timeout: 3초
        );
        socket.setSoTimeout(10000); // Read Timeout: 10초
        socket.setKeepAlive(true);
        return socket;
    }

    @Override
    public boolean validateObject(PooledObject<Socket> p) {
        Socket socket = p.getObject();
        return socket != null && socket.isConnected() && !socket.isClosed();
    }

    @Override
    public void destroyObject(PooledObject<Socket> p) throws Exception {
        Socket socket = p.getObject();
        if (socket != null && !socket.isClosed()) {
            socket.close();
        }
    }

    @Override
    public PooledObject<Socket> wrap(Socket socket) {
        return new DefaultPooledObject<>(socket);
    }
}
```

### 재시도 전략: Resilience4j 활용

재시도는 단순 루프가 아니다. **지수 백오프(Exponential Backoff)** 와 **Jitter**를 함께 적용해야 한다.

```java
@Configuration
public class RetryConfig {

    @Bean
    public Retry externalAgencyRetry() {
        RetryConfig config = RetryConfig.custom()
            .maxAttempts(3)
            .waitDuration(Duration.ofMillis(500))
            // 지수 백오프: 500ms -> 1000ms -> 2000ms
            .intervalFunction(IntervalFunction.ofExponentialBackoff(500, 2.0))
            // 재시도 대상 예외 한정 (비즈니스 오류는 재시도 안 함)
            .retryExceptions(SocketTimeoutException.class, ConnectException.class)
            .ignoreExceptions(BusinessException.class)
            .build();

        return Retry.of("externalAgency", config);
    }
}

@Service
@RequiredArgsConstructor
public class ExternalAgencyClient {

    private final GenericObjectPool<Socket> socketPool;
    private final Retry externalAgencyRetry;

    public MessageFrame send(MessageFrame request) {
        Supplier<MessageFrame> sendSupplier = Retry.decorateSupplier(
            externalAgencyRetry,
            () -> doSend(request)
        );

        return Try.ofSupplier(sendSupplier)
            .getOrElseThrow(e -> new ExternalAgencyException("대외기관 통신 실패", e));
    }

    private MessageFrame doSend(MessageFrame request) {
        Socket socket = null;
        try {
            socket = socketPool.borrowObject();
            byte[] requestBytes = request.serialize(request.getBody());

            // 전송
            OutputStream out = socket.getOutputStream();
            out.write(requestBytes);
            out.flush();

            // 수신: 헤더 먼저 읽고, 전체 길이 파악 후 바디 수신
            InputStream in = socket.getInputStream();
            byte[] headerBytes = readFully(in, MessageFrame.HEADER_LENGTH);
            int totalLength = Integer.parseInt(
                new String(Arrays.copyOfRange(headerBytes, 0, 4), "EUC-KR").trim()
            );
            byte[] bodyBytes = readFully(in, totalLength - MessageFrame.HEADER_LENGTH);

            byte[] fullResponse = ByteBuffer.allocate(totalLength)
                .put(headerBytes).put(bodyBytes).array();

            return MessageFrame.deserialize(fullResponse);

        } catch (SocketTimeoutException e) {
            // 타임아웃 시 소켓을 무효화하여 풀에 반환하지 않음
            invalidateSocket(socket);
            socket = null;
            throw e;
        } catch (Exception e) {
            invalidateSocket(socket);
            socket = null;
            throw new RuntimeException(e);
        } finally {
            returnSocket(socket);
        }
    }

    private byte[] readFully(InputStream in, int length) throws IOException {
        byte[] buffer = new byte[length];
        int offset = 0;
        while (offset < length) {
            int read = in.read(buffer, offset, length - offset);
            if (read == -1) throw new IOException("Connection closed by remote");
            offset += read;
        }
        return buffer;
    }

    private void invalidateSocket(Socket socket) {
        if (socket != null) {
            try { socketPool.invalidateObject(socket); } catch (Exception ignored) {}
        }
    }

    private void returnSocket(Socket socket) {
        if (socket != null) {
            try { socketPool.returnObject(socket); } catch (Exception ignored) {}
        }
    }
}
```

## 주의사항 및 트레이드오프

### 1. 재시도는 독(毒)이 될 수 있다

재시도 로직을 잘못 설계하면 **이중 처리(Duplicate Processing)** 문제가 발생한다. 금융 거래에서 이체 요청이 성공했는데 응답 수신 전에 타임아웃이 발생하면, 재시도 시 동일 거래가 두 번 처리될 수 있다.

이를 방지하기 위해 반드시 **전문일련번호(Sequence Number)** 기반의 멱등성 설계가 필요하다. 대외기관이 중복 전문을 감지할 수 없다면, 재시도 전 **거래 상태 조회 전문**을 먼저 보내는 패턴을 고려해야 한다.

```
재시도 안전 판단 흐름:
SocketTimeout 발생 → 원거래 결과 조회 전문 전송 → 성공이면 재시도 X, 실패/미처리면 재시도
```

### 2. 타임아웃 값은 SLA 기반으로 설정하라

타임아웃은 감으로 잡는 것이 아니다. 대외기관과 맺은 SLA(Service Level Agreement)의 응답 보장 시간을 기준으로, 여기에 네트워크 레이턴시 버퍼를 더해 설정해야 한다. 너무 짧으면 정상 처리도 실패 처리되고, 너무 길면 스레드 풀이 고갈된다.

### 3. Stale Connection 처리

Long Connection 방식에서 네트워크 장비(방화벽, L4 등)가 일정 시간 이상 유휴 상태인 연결을 강제로 끊는 경우가 있다. 이때 클라이언트는 연결이 살아 있다고 판단하지만 실제로는 끊긴 **Half-Open Connection** 상태가 된다.

대응 방법은 두 가지다.

- **Heartbeat 전문**: 주기적으로 더미 전문을 전송해 연결을 유지
- **TestOnBorrow 강화**: 풀에서 소켓을 빌릴 때 실제 읽기/쓰기 가능 여부를 확인

### 4. 인코딩 문제

EUC-KR을 사용하는 기관은 아직도 많다. 한글 필드의 바이트 길이 계산 시 `string.length()`가 아니라 `string.getBytes(charset).length`를 사용해야 한다. 이를 혼동하면 필드 경계가 밀려 전문 파싱 전체가 틀어진다.

### 5. 모니터링: 무엇을 메트릭으로 남길 것인가

대외기관 연계는 블랙박스 영역이다. 최소한 아래 항목은 메트릭으로 수집해야 한다.

- 전문 종류별 응답 시간 분포 (p50, p95, p99)
- 타임아웃 발생 횟수 및 비율
- 재시도 발생 횟수
- 커넥션 풀 사용률 (active/idle/waiting)
- 응답 코드별 집계

## 정리

대외기관 연계 시스템은 단순한 HTTP 클라이언트 코드와는 차원이 다른 복잡성을 가진다. 핵심을 정리하면 다음과 같다.

| 항목 | 핵심 포인트 |
|---|---|
| 전문 통신 | 고정 길이 직렬화/역직렬화, 인코딩(EUC-KR) 주의 |
| 커넥션 풀 | Long Connection + TestOnBorrow + Heartbeat |
| 타임아웃 | Connect / Read / Write 타임아웃을 분리하여 SLA 기반으로 설정 |
| 재시도 | 지수 백오프 + Jitter, 멱등성 보장 여부 선확인 |
| 모니터링 | 응답 시간 분포, 타임아웃/재시도 횟수, 풀 사용률 |

대외기관 연계를 처음 맡게 되면 명세서의 방대한 전문 구조에 압도되기 쉽다. 그러나 결국 핵심은 **"안정적인 연결 관리 + 명확한 실패 처리 경계"** 다. 타임아웃과 재시도 전략을 먼저 설계하고, 그 위에 전문 직렬화 로직을 얹는 순서로 접근하면 훨씬 견고한 시스템을 만들 수 있다.
