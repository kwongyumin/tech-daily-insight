# WebRTC 실시간 P2P 통신 백엔드 시그널링 서버

## 개요

WebRTC(Web Real-Time Communication)는 브라우저 및 모바일 앱 간에 플러그인 없이 실시간 음성, 영상, 데이터를 교환할 수 있게 해주는 오픈 표준이다. 하지만 "P2P"라는 단어에 현혹되어 백엔드가 필요 없다고 오해하는 경우가 많다.

실제로 WebRTC 피어 간 직접 연결이 성립되기 전, 반드시 **시그널링(Signaling)** 과정이 필요하다. 시그널링 서버는 두 피어가 서로를 "발견"하고 연결 협상을 할 수 있도록 중개자 역할을 담당한다. 이 포스팅에서는 시그널링 서버의 핵심 개념부터 Spring Boot + WebSocket 기반의 실전 구현, 그리고 운영 시 고려해야 할 트레이드오프까지 다룬다.

---

## 핵심 개념

### 시그널링이 필요한 이유

WebRTC가 P2P 연결을 맺으려면 두 피어 간에 다음 정보를 교환해야 한다.

- **SDP(Session Description Protocol)**: 미디어 포맷, 코덱, 해상도 등 세션 정보
- **ICE Candidate**: 피어에 도달할 수 있는 네트워크 경로 후보 (IP/Port)

이 정보를 교환하는 채널이 바로 시그널링 서버다. WebRTC 표준은 시그널링 방식을 명세하지 않기 때문에 WebSocket, SSE, HTTP Long-polling 등 어떤 방식을 사용해도 무방하다.

### WebRTC 연결 수립 흐름

```
Peer A                  Signaling Server              Peer B
  |                           |                          |
  |--- createOffer() -------> |                          |
  |    (SDP Offer)            |--- forward Offer ------> |
  |                           |                          |-- createAnswer()
  |                           | <-- SDP Answer ----------|
  | <-- forward Answer -------|                          |
  |                           |                          |
  |--- ICE Candidate -------> |--- forward Candidate --> |
  | <-- ICE Candidate --------|  <-- ICE Candidate ------|
  |                           |                          |
  |============= P2P Connection Established =============|
```

### STUN / TURN 서버의 역할

| 서버 | 역할 | 비용 |
|------|------|------|
| STUN | 공인 IP/Port 확인 (NAT 통과 시도) | 낮음 |
| TURN | NAT 통과 실패 시 미디어 릴레이 | 높음 (대역폭 소모) |
| Signaling | SDP/ICE 메시지 중개 | 낮음 |

STUN만으로 연결이 되는 경우는 약 75~80%이며, 나머지는 TURN 서버를 경유해야 한다. 프로덕션 환경에서는 반드시 TURN 서버를 구축하거나 Twilio, Xirsys 같은 관리형 서비스를 사용해야 한다.

## 실전 예제

### 프로젝트 구성

Spring Boot 3.x + WebSocket (STOMP) 기반으로 시그널링 서버를 구현한다.

**build.gradle**

```groovy
dependencies {
    implementation 'org.springframework.boot:spring-boot-starter-websocket'
    implementation 'org.springframework.boot:spring-boot-starter-data-redis'
    implementation 'org.springframework.session:spring-session-data-redis'
    implementation 'com.fasterxml.jackson.core:jackson-databind'
    compileOnly 'org.projectlombok:lombok'
    annotationProcessor 'org.projectlombok:lombok'
}
```

### WebSocket 설정

```java
@Configuration
@EnableWebSocketMessageBroker
public class WebSocketConfig implements WebSocketMessageBrokerConfigurer {

    @Override
    public void configureMessageBroker(MessageBrokerRegistry registry) {
        // 클라이언트 구독 prefix
        registry.enableSimpleBroker("/topic", "/queue");
        // 클라이언트 -> 서버 메시지 prefix
        registry.setApplicationDestinationPrefixes("/app");
        // 특정 유저에게 메시지 전송 prefix
        registry.setUserDestinationPrefix("/user");
    }

    @Override
    public void registerStompEndpoints(StompEndpointRegistry registry) {
        registry.addEndpoint("/ws-signaling")
                .setAllowedOriginPatterns("*")
                .withSockJS(); // SockJS fallback 지원
    }
}
```

### 시그널링 메시지 모델

```java
@Getter
@Setter
@NoArgsConstructor
@AllArgsConstructor
public class SignalingMessage {

    public enum Type {
        OFFER, ANSWER, ICE_CANDIDATE, JOIN, LEAVE
    }

    private Type type;
    private String roomId;
    private String senderId;
    private String targetId;   // 특정 피어 대상 (null이면 브로드캐스트)
    private Object payload;    // SDP 또는 ICE Candidate 데이터
}
```

### 룸 관리 서비스

```java
@Service
@Slf4j
@RequiredArgsConstructor
public class RoomService {

    // 실제 운영 환경에서는 Redis로 대체
    private final ConcurrentHashMap<String, Set<String>> rooms = new ConcurrentHashMap<>();

    public Set<String> joinRoom(String roomId, String sessionId) {
        rooms.computeIfAbsent(roomId, k -> ConcurrentHashMap.newKeySet())
             .add(sessionId);
        log.info("Session {} joined room {}", sessionId, roomId);
        return getPeers(roomId, sessionId);
    }

    public void leaveRoom(String roomId, String sessionId) {
        Set<String> participants = rooms.get(roomId);
        if (participants != null) {
            participants.remove(sessionId);
            if (participants.isEmpty()) {
                rooms.remove(roomId);
            }
        }
        log.info("Session {} left room {}", sessionId, roomId);
    }

    public Set<String> getPeers(String roomId, String excludeSessionId) {
        return rooms.getOrDefault(roomId, Collections.emptySet())
                    .stream()
                    .filter(id -> !id.equals(excludeSessionId))
                    .collect(Collectors.toSet());
    }

    public int getRoomSize(String roomId) {
        return rooms.getOrDefault(roomId, Collections.emptySet()).size();
    }
}
```

### 시그널링 컨트롤러

```java
@Controller
@Slf4j
@RequiredArgsConstructor
public class SignalingController {

    private final SimpMessagingTemplate messagingTemplate;
    private final RoomService roomService;

    /**
     * 룸 입장 처리
     * 기존 참여자 목록을 신규 입장자에게, 신규 입장 알림을 기존 참여자에게 전송
     */
    @MessageMapping("/join")
    public void handleJoin(SignalingMessage message, SimpMessageHeaderAccessor accessor) {
        String sessionId = accessor.getSessionId();
        String roomId = message.getRoomId();

        // 룸 최대 인원 제한 (1:1 통화 기준)
        if (roomService.getRoomSize(roomId) >= 2) {
            messagingTemplate.convertAndSendToUser(
                sessionId, "/queue/error",
                Map.of("message", "Room is full", "roomId", roomId)
            );
            return;
        }

        Set<String> existingPeers = roomService.joinRoom(roomId, sessionId);

        // 신규 참가자에게 기존 피어 목록 전달
        messagingTemplate.convertAndSendToUser(
            sessionId, "/queue/peers",
            Map.of("peers", existingPeers, "roomId", roomId)
        );

        // 기존 참가자들에게 신규 참가자 알림
        existingPeers.forEach(peerId ->
            messagingTemplate.convertAndSendToUser(
                peerId, "/queue/peer-joined",
                Map.of("peerId", sessionId, "roomId", roomId)
            )
        );

        log.info("User {} joined room {}. Current peers: {}", sessionId, roomId, existingPeers);
    }

    /**
     * SDP Offer/Answer 및 ICE Candidate 중계
     */
    @MessageMapping("/signal")
    public void handleSignal(SignalingMessage message, SimpMessageHeaderAccessor accessor) {
        String senderId = accessor.getSessionId();
        message.setSenderId(senderId);

        log.debug("Signal [{}] from {} to {} in room {}",
            message.getType(), senderId, message.getTargetId(), message.getRoomId());

        if (message.getTargetId() != null) {
            // 특정 피어에게 1:1 전송
            messagingTemplate.convertAndSendToUser(
                message.getTargetId(), "/queue/signal", message
            );
        } else {
            // 룸 내 전체 브로드캐스트 (자신 제외)
            roomService.getPeers(message.getRoomId(), senderId)
                       .forEach(peerId ->
                           messagingTemplate.convertAndSendToUser(
                               peerId, "/queue/signal", message
                           )
                       );
        }
    }

    /**
     * 연결 종료 처리
     */
    @MessageMapping("/leave")
    public void handleLeave(SignalingMessage message, SimpMessageHeaderAccessor accessor) {
        String sessionId = accessor.getSessionId();
        String roomId = message.getRoomId();

        Set<String> peers = roomService.getPeers(roomId, sessionId);
        roomService.leaveRoom(roomId, sessionId);

        // 남은 피어들에게 퇴장 알림
        peers.forEach(peerId ->
            messagingTemplate.convertAndSendToUser(
                peerId, "/queue/peer-left",
                Map.of("peerId", sessionId, "roomId", roomId)
            )
        );
    }

    /**
     * WebSocket 연결 해제 이벤트 처리 (비정상 종료 대응)
     */
    @EventListener
    public void handleSessionDisconnect(SessionDisconnectEvent event) {
        String sessionId = event.getSessionId();
        log.info("Session disconnected: {}", sessionId);
        // 실제로는 세션-룸 매핑 정보를 별도로 관리하여 처리
    }
}
```

### 클라이언트 사이드 연동 예시 (JavaScript)

```javascript
const stompClient = new StompJs.Client({
  webSocketFactory: () => new SockJS('/ws-signaling')
});

stompClient.onConnect = (frame) => {
  const sessionId = frame.headers['user-name'];

  // 시그널 수신 구독
  stompClient.subscribe('/user/queue/signal', async (message) => {
    const signal = JSON.parse(message.body);

    if (signal.type === 'OFFER') {
      await peerConnection.setRemoteDescription(signal.payload);
      const answer = await peerConnection.createAnswer();
      await peerConnection.setLocalDescription(answer);
      sendSignal('ANSWER', answer, signal.senderId);
    } else if (signal.type === 'ANSWER') {
      await peerConnection.setRemoteDescription(signal.payload);
    } else if (signal.type === 'ICE_CANDIDATE') {
      await peerConnection.addIceCandidate(signal.payload);
    }
  });

  // ICE Candidate 수집 시 시그널링 서버로 전송
  peerConnection.onicecandidate = ({ candidate }) => {
    if (candidate) sendSignal('ICE_CANDIDATE', candidate, targetPeerId);
  };

  stompClient.publish({
    destination: '/app/join',
    body: JSON.stringify({ roomId: 'room-001' })
  });
};

function sendSignal(type, payload, targetId) {
  stompClient.publish({
    destination: '/app/signal',
    body: JSON.stringify({ type, payload, targetId, roomId: 'room-001' })
  });
}
```

## 주의사항 및 트레이드오프

### 1. 수평 확장(Scale-out) 문제

단일 서버 `SimpMessagingTemplate`은 같은 인스턴스 내 세션만 접근 가능하다. 다중 인스턴스 환경에서는 **Redis Pub/Sub**를 메시지 브로커로 도입해야 한다.

```java
// Redis 기반 메시지 브로커로 교체
@Override
public void configureMessageBroker(MessageBrokerRegistry registry) {
    registry.enableStompBrokerRelay("/topic", "/queue")
            .setRelayHost("localhost")
            .setRelayPort(61613); // RabbitMQ STOMP 포트
}
```

RabbitMQ의 STOMP 플러그인을 활성화하거나, Redis Streams를 직접 활용하는 방식이 일반적이다.

### 2. 세션 관리와 비정상 종료

WebSocket 연결이 비정상적으로 끊길 경우, 룸에 고스트 세션이 남을 수 있다. `SessionDisconnectEvent`를 반드시 처리하고, 세션-룸 매핑 정보를 **TTL이 설정된 Redis**에 저장해 자동 만료되도록 설계해야 한다.

### 3. 보안 고려사항

- **인증**: WebSocket 핸드셰이크 시점에 JWT 검증을 수행
- **룸 접근 제어**: 임의의 `roomId`로 입장하지 못하도록 서버 사이드 검증
- **Origin 검증**: `setAllowedOriginPatterns("*")` 는 개발 환경에서만 사용

```java
@Override
public boolean beforeHandshake(ServerHttpRequest request, ...) {
    // JWT 검증 로직 추가
    String token = extractToken(request);
    return jwtService.isValid(token);
}
```

### 4. TURN 서버 비용 vs. 연결 품질

TURN 서버를 자체 구축하면 비용을 절감할 수 있지만 운영 부담이 증가한다. 소규모 서비스라면 Twilio, Xirsys 같은 관리형 서비스를 권장한다. 대규모 트래픽에서는 coturn 오픈소스를 직접 운영하거나 CDN 엣지 서버를 활용하는 아키텍처가 유리하다.

### 5. 시그널링 서버는 경량화하라

시그널링 서버는 미디어 데이터를 전혀 처리하지 않는다. 복잡한 비즈니스 로직을 넣기보다 **메시지 라우팅에만 집중**하고, 미디어 처리가 필요하다면 별도 SFU(Selective Forwarding Unit) 서버(mediasoup, Janus, Kurento 등)를 분리 운영해야 한다.

## 정리

| 구성 요소 | 역할 | 기술 선택 |
|-----------|------|-----------|
| 시그널링 서버 | SDP/ICE 메시지 중개 | Spring Boot + WebSocket(STOMP) |
| 룸 상태 관리 | 세션/룸 매핑 | Redis (TTL 적용) |
| 메시지 브로커 | 다중 인스턴스 메시지 동기화 | RabbitMQ / Redis Pub-Sub |
| STUN 서버 | 공인 IP 확인 | Google STUN (개발), 자체 구축 (운영) |
| TURN 서버 | NAT 통과 실패 시 릴레이 | coturn / Twilio |

WebRTC 시그널링 서버는 기술적으로 단순해 보이지만, **수평 확장**, **비정상 종료 처리**, **보안** 세 가지를 제대로 설계하지 않으면 운영 환경에서 반드시 문제가 생긴다. 핵심은 시그널링 서버를 가볍게 유지하면서 상태는 Redis에 위임하고, 미디어 처리가 필요하다면 SFU로 분리하는 아키텍처를 선택하는 것이다.

소규모 1:1 통화라면 이 포스팅의 구현으로 충분하지만, 다자간 회의나 라이브 스트리밍까지 확장한다면 mediasoup 같은 SFU와의 통합을 다음 단계로 고려해보길 권장한다.
