# 블록체인 지갑과 개인키 보안 관리 방법

## 개요

블록체인 개발에서 가장 중요하면서도 자주 간과되는 영역이 바로 **지갑(Wallet)과 개인키(Private Key) 보안 관리**다. 중앙화된 시스템과 달리 블록체인에서는 개인키를 분실하거나 탈취당하면 자산을 영구적으로 복구할 수 없다. 서버사이드에서 사용자 자산을 다루는 서비스를 개발한다면, 이 문제는 곧 비즈니스 생사와 직결된다.

이 글에서는 블록체인 지갑의 핵심 개념부터, 실무에서 바로 적용 가능한 개인키 보안 관리 전략과 코드 예제를 다룬다. 특히 Java/Spring 환경에서 custodial 서비스를 구축하거나, 사용자 지갑을 관리해야 하는 백엔드 개발자를 대상으로 한다.

---

## 핵심 개념

### 1. 지갑의 종류

블록체인 지갑은 크게 세 가지 관리 방식으로 나뉜다.

| 유형 | 설명 | 보안 수준 | 사용 편의성 |
|------|------|-----------|-------------|
| **Custodial Wallet** | 서비스 제공자가 개인키를 보관 | 서비스 신뢰에 의존 | 높음 |
| **Non-Custodial Wallet** | 사용자가 직접 개인키 보관 | 사용자 책임 | 낮음 |
| **MPC Wallet** | 키를 분산하여 공동 관리 | 매우 높음 | 중간 |

백엔드 개발자가 다루는 영역은 주로 **Custodial** 방식이며, 이 경우 서버가 개인키를 안전하게 보관하고 서명을 대행해야 한다.

### 2. HD Wallet과 BIP-39/BIP-44

**HD Wallet(Hierarchical Deterministic Wallet)**은 하나의 마스터 시드(Seed)에서 계층적으로 무수히 많은 키 쌍을 파생하는 구조다. BIP-39는 니모닉(Mnemonic) 단어 목록으로 시드를 생성하는 표준이고, BIP-44는 경로(Path) 규약을 정의한다.

```
m / purpose' / coin_type' / account' / change / address_index
m / 44'      / 60'        / 0'       / 0      / 0
```

이 구조 덕분에 하나의 마스터 키만 안전하게 보관하면 수백만 개의 주소를 파생할 수 있다.

### 3. 개인키의 물리적 구조

이더리움 기준으로 개인키는 256비트(32바이트) 난수이며, 이로부터 공개키와 주소가 파생된다.

```
Private Key (256 bit) 
    → ECDSA secp256k1 → Public Key (512 bit)
    → Keccak-256 Hash → Address (160 bit = 20 bytes)
```

## 실전 예제

### 1. Java에서 HD Wallet 생성 (Web3j + bitcoinj)

```xml
<!-- pom.xml -->
<dependency>
    <groupId>org.web3j</groupId>
    <artifactId>core</artifactId>
    <version>4.10.3</version>
</dependency>
<dependency>
    <groupId>org.bitcoinj</groupId>
    <artifactId>bitcoinj-core</artifactId>
    <version>0.16.2</version>
</dependency>
```

```java
import org.bitcoinj.crypto.*;
import org.bitcoinj.wallet.DeterministicSeed;
import org.web3j.crypto.*;
import org.web3j.utils.Numeric;

import java.security.SecureRandom;
import java.util.List;

public class HdWalletService {

    private static final String ETH_DERIVATION_PATH = "m/44'/60'/0'/0/";

    /**
     * 신규 마스터 시드 생성 (최초 1회만 실행)
     */
    public String generateMnemonic() {
        byte[] entropy = new byte[16]; // 128 bit → 12 words
        new SecureRandom().nextBytes(entropy);
        List<String> mnemonic = MnemonicCode.INSTANCE.toMnemonic(entropy);
        return String.join(" ", mnemonic);
    }

    /**
     * 니모닉으로부터 특정 인덱스의 자식 키 파생
     */
    public ECKeyPair deriveChildKey(String mnemonic, int index) throws Exception {
        byte[] seed = MnemonicCode.toSeed(
            List.of(mnemonic.split(" ")), ""
        );

        DeterministicKey masterKey = HDKeyDerivation.createMasterPrivateKey(seed);
        String fullPath = ETH_DERIVATION_PATH + index;

        DeterministicKey childKey = masterKey;
        for (ChildNumber pathElement : HDUtils.parsePath(fullPath)) {
            childKey = HDKeyDerivation.deriveChildKey(childKey, pathElement);
        }

        byte[] privateKeyBytes = childKey.getPrivKeyBytes();
        return ECKeyPair.create(privateKeyBytes);
    }

    /**
     * 키 쌍으로부터 이더리움 주소 획득
     */
    public String getAddress(ECKeyPair keyPair) {
        return Keys.toChecksumAddress(
            Keys.getAddress(keyPair.getPublicKey())
        );
    }
}
```

### 2. AWS KMS를 활용한 마스터 시드 암호화 보관

실무에서 마스터 시드를 평문으로 DB에 저장하는 것은 절대 금물이다. AWS KMS나 HashiCorp Vault를 이용해 봉투 암호화(Envelope Encryption)를 적용해야 한다.

```java
import software.amazon.awssdk.services.kms.KmsClient;
import software.amazon.awssdk.services.kms.model.*;
import software.amazon.awssdk.core.SdkBytes;

import javax.crypto.Cipher;
import javax.crypto.KeyGenerator;
import javax.crypto.SecretKey;
import javax.crypto.spec.GCMParameterSpec;
import java.util.Base64;

@Service
public class KmsEncryptionService {

    private final KmsClient kmsClient;

    @Value("${aws.kms.key-id}")
    private String kmsKeyId;

    /**
     * 봉투 암호화: 데이터 키를 생성하고 KMS로 데이터 키를 암호화
     */
    public EncryptedSeedResult encryptMasterSeed(byte[] masterSeed) throws Exception {
        // 1. KMS에서 데이터 키 생성
        GenerateDataKeyResponse dataKeyResponse = kmsClient.generateDataKey(
            GenerateDataKeyRequest.builder()
                .keyId(kmsKeyId)
                .keySpec(DataKeySpec.AES_256)
                .build()
        );

        byte[] plainDataKey = dataKeyResponse.plaintext().asByteArray();
        byte[] encryptedDataKey = dataKeyResponse.ciphertextBlob().asByteArray();

        // 2. AES-GCM으로 마스터 시드 암호화
        byte[] iv = new byte[12];
        new SecureRandom().nextBytes(iv);

        Cipher cipher = Cipher.getInstance("AES/GCM/NoPadding");
        cipher.init(Cipher.ENCRYPT_MODE,
            new javax.crypto.spec.SecretKeySpec(plainDataKey, "AES"),
            new GCMParameterSpec(128, iv)
        );
        byte[] encryptedSeed = cipher.doFinal(masterSeed);

        // 3. plaintext 데이터 키는 메모리에서 즉시 소거
        java.util.Arrays.fill(plainDataKey, (byte) 0);

        return new EncryptedSeedResult(
            Base64.getEncoder().encodeToString(encryptedDataKey),
            Base64.getEncoder().encodeToString(iv),
            Base64.getEncoder().encodeToString(encryptedSeed)
        );
    }

    /**
     * 복호화: KMS로 데이터 키를 복호화 후 시드 복호화
     */
    public byte[] decryptMasterSeed(EncryptedSeedResult encrypted) throws Exception {
        // 1. KMS로 데이터 키 복호화
        DecryptResponse decryptResponse = kmsClient.decrypt(
            DecryptRequest.builder()
                .ciphertextBlob(SdkBytes.fromByteArray(
                    Base64.getDecoder().decode(encrypted.encryptedDataKey())
                ))
                .keyId(kmsKeyId)
                .build()
        );

        byte[] plainDataKey = decryptResponse.plaintext().asByteArray();
        byte[] iv = Base64.getDecoder().decode(encrypted.iv());
        byte[] encryptedSeed = Base64.getDecoder().decode(encrypted.encryptedSeed());

        // 2. 시드 복호화
        Cipher cipher = Cipher.getInstance("AES/GCM/NoPadding");
        cipher.init(Cipher.DECRYPT_MODE,
            new javax.crypto.spec.SecretKeySpec(plainDataKey, "AES"),
            new GCMParameterSpec(128, iv)
        );
        byte[] seed = cipher.doFinal(encryptedSeed);

        // 3. 데이터 키 메모리 소거
        java.util.Arrays.fill(plainDataKey, (byte) 0);

        return seed;
    }
}
```

### 3. 트랜잭션 서명 서비스 (키를 외부 노출 없이 처리)

```java
@Service
@Transactional
public class TransactionSigningService {

    private final KmsEncryptionService kmsService;
    private final HdWalletService hdWalletService;
    private final Web3j web3j;

    /**
     * 개인키를 메모리에서만 사용하고 즉시 소거하는 서명 처리
     */
    public String signAndSendTransaction(
            String encryptedMasterSeedJson,
            int walletIndex,
            String toAddress,
            BigInteger value) throws Exception {

        byte[] masterSeed = null;
        ECKeyPair keyPair = null;

        try {
            // 시드 복호화
            masterSeed = kmsService.decryptMasterSeed(
                parseEncryptedSeed(encryptedMasterSeedJson)
            );

            // 자식 키 파생
            keyPair = hdWalletService.deriveChildKey(
                new String(masterSeed), walletIndex
            );

            // 트랜잭션 빌드 및 서명
            EthGetTransactionCount ethGetTransactionCount = web3j
                .ethGetTransactionCount(
                    hdWalletService.getAddress(keyPair),
                    DefaultBlockParameterName.LATEST
                ).send();

            RawTransaction rawTransaction = RawTransaction.createEtherTransaction(
                ethGetTransactionCount.getTransactionCount(),
                DefaultGasProvider.GAS_PRICE,
                DefaultGasProvider.GAS_LIMIT,
                toAddress,
                value
            );

            Credentials credentials = Credentials.create(keyPair);
            byte[] signedMessage = TransactionEncoder.signMessage(rawTransaction, credentials);
            String hexValue = Numeric.toHexString(signedMessage);

            EthSendTransaction ethSendTransaction = web3j
                .ethSendRawTransaction(hexValue).send();

            return ethSendTransaction.getTransactionHash();

        } finally {
            // 민감 데이터 메모리 소거
            if (masterSeed != null) java.util.Arrays.fill(masterSeed, (byte) 0);
            // ECKeyPair의 경우 BigInteger라 직접 소거 불가 → GC 유도
            keyPair = null;
            System.gc();
        }
    }
}
```

## 주의사항 및 트레이드오프

### ⚠️ 절대 하지 말아야 할 것들

1. **개인키/니모닉을 로그에 출력하지 말 것**
   - MDC 필터, AOP 등에서 실수로 포함될 수 있으므로 Sensitive 데이터 마스킹 라이브러리를 사용한다.

2. **환경 변수나 application.yml에 평문 키 저장 금지**
   - Secrets Manager(AWS), Vault(HashiCorp), GCP Secret Manager를 반드시 사용한다.

3. **키 파생 후 메모리 즉시 소거**
   - Java의 `String`은 불변 객체라 메모리 소거가 어려우므로, 민감 데이터는 `byte[]`나 `char[]`로 다루고 사용 후 `Arrays.fill()`로 덮어쓴다.

### 🔄 아키텍처 트레이드오프

| 방식 | 장점 | 단점 |
|------|------|------|
| **HSM(Hardware Security Module)** | 최고 수준의 키 보안 | 비용이 매우 높음 |
| **AWS KMS** | 관리형, 감사 로그 | 클라우드 벤더 의존성 |
| **HashiCorp Vault** | 자체 호스팅 가능, 유연성 | 운영 복잡도 증가 |
| **MPC (Multi-Party Computation)** | 단일 실패점 제거 | 구현 복잡도 높음, 레이턴시 |
| **소프트웨어 암호화만 사용** | 간단한 구현 | 서버 침해 시 위험 |

### 🔐 접근 제어 원칙

- **최소 권한 원칙(Principle of Least Privilege)**: 서명 서비스는 해당 KMS 키에 대한 `kms:Decrypt`, `kms:GenerateDataKey` 권한만 보유
- **서명 서비스 격리**: 키를 다루는 마이크로서비스는 네트워크 정책으로 외부 직접 접근을 차단하고, 내부 서비스에서만 호출 허용
- **감사 로깅**: 모든 서명 요청에 요청자, 타임스탬프, 대상 주소를 불변 감사 로그(Append-only)로 기록

### 🛡️ 추가 방어 레이어

```yaml
# Spring Security + Vault 통합 예시 (application.yml)

```

## 정리

블록체인 지갑과 개인키 보안은 단순한 암호화 이상의 **심층 방어(Defense in Depth)** 전략이 필요하다.

핵심 원칙을 요약하면 다음과 같다.

1. **HD Wallet 구조**로 단일 마스터 시드에서 모든 주소를 파생하여, 보관 대상을 최소화한다.
2. **봉투 암호화 + KMS/HSM**으로 마스터 시드를 이중 보호한다.
3. **개인키는 메모리에서만 존재**해야 하며, 사용 직후 반드시 소거한다.
4. **서명 서비스는 격리**하고, 모든 접근에 감사 로그를 남긴다.
5. 높은 보안이 필요하다면 **MPC Wallet** 도입을 검토하되, 구현 복잡도와 레이턴시를 감수해야 한다.

암호화폐 거래소, DeFi 프로토콜, NFT 마켓플레이스 등 실제 자산을 다루는 서비스라면 보안 감사(Security Audit)를 정기적으로 수행하고, 주요 취약점(CVE)을 모니터링하는 것도 필수다. 개인키 보안은 한 번 구축하고 끝내는 것이 아니라, 지속적으로 점검하고 강화해야 하는 생명주기 관리의 영역임을 명심하자.
