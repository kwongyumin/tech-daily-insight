# 엣지 컴퓨팅과 CDN 엣지 함수 활용 전략

## 개요

전통적인 웹 아키텍처는 단일 리전의 중앙 서버에서 모든 요청을 처리했다. 사용자가 서울에 있든 뉴욕에 있든, 모든 트래픽은 오리진 서버를 거쳐야 했고, 물리적 거리에서 발생하는 레이턴시는 피할 수 없는 숙명이었다.

엣지 컴퓨팅은 이 패러다임을 뒤집는다. **사용자와 가장 가까운 네트워크 엣지(PoP, Point of Presence)에서 연산을 수행**함으로써 레이턴시를 수십 밀리초 단위로 줄이고, 오리진 서버의 부하를 극적으로 낮출 수 있다.

Cloudflare Workers, Vercel Edge Functions, AWS Lambda@Edge, Fastly Compute@Edge 같은 플랫폼들이 이 개념을 실용적으로 구현하고 있으며, 현재 많은 프로덕션 서비스들이 이를 활용해 성능과 비용 두 마리 토끼를 잡고 있다. 이 글에서는 엣지 함수의 핵심 개념부터 실전 패턴, 그리고 반드시 고려해야 할 트레이드오프까지 실무 관점에서 짚어본다.

---

## 핵심 개념

### 엣지 컴퓨팅이란?

엣지 컴퓨팅은 데이터를 생성하는 소스 또는 소비하는 사용자 **근처에서 연산을 처리**하는 분산 컴퓨팅 패러다임이다. CDN 맥락에서는 Cloudflare의 300개 이상, Fastly의 80개 이상 PoP처럼 전 세계에 분산된 노드에서 코드를 실행하는 것을 의미한다.

핵심 특징을 정리하면:

- **초저 레이턴시**: 사용자와 10~50ms 거리의 노드에서 실행
- **V8 Isolate 기반 실행 환경**: Node.js나 JVM이 아닌 경량 V8 Isolate로 콜드 스타트가 0ms에 가까움
- **제한된 런타임**: 전통적인 서버리스보다 훨씬 적은 메모리와 CPU, 실행 시간 제한
- **Web API 기반**: `fetch`, `Request`, `Response`, `crypto` 등 표준 Web API 사용

### 엣지 함수 vs 기존 서버리스

| 항목 | 엣지 함수 (Workers 등) | 기존 서버리스 (Lambda 등) |
|------|----------------------|------------------------|
| 실행 위치 | 사용자 근접 PoP | 단일/멀티 리전 |
| 콜드 스타트 | ~0ms (Isolate) | 수백ms ~ 수초 |
| 메모리 한도 | 128MB (Cloudflare) | 최대 10GB |
| 실행 시간 | 50ms CPU (무료) | 최대 15분 |
| 런타임 | JS/WASM (제한적) | Node, Python, Java 등 |
| 상태 저장 | KV, Durable Objects | DynamoDB, RDS 등 |

## 실전 예제

### 1. A/B 테스트를 엣지에서 처리하기

오리진 서버나 클라이언트 JS 없이 엣지에서 A/B 테스트 라우팅을 구현할 수 있다. 쿠키 기반으로 일관성 있는 사용자 경험을 보장하면서, 오리진 부하 없이 수행한다.

```javascript
// Cloudflare Workers - A/B Test Edge Routing
export default {
  async fetch(request, env) {
    const url = new URL(request.url);

    // 기존 쿠키에서 variant 읽기
    const cookie = request.headers.get('Cookie') || '';
    const variantMatch = cookie.match(/ab_variant=(A|B)/);
    let variant = variantMatch ? variantMatch[1] : null;

    // 신규 사용자: 50/50으로 배정
    if (!variant) {
      variant = Math.random() < 0.5 ? 'A' : 'B';
    }

    // variant에 따라 다른 오리진으로 라우팅
    const targetOrigin = variant === 'A'
      ? 'https://v1.example.com'
      : 'https://v2.example.com';

    const targetUrl = `${targetOrigin}${url.pathname}${url.search}`;
    const response = await fetch(targetUrl, {
      method: request.method,
      headers: request.headers,
      body: request.body,
    });

    // 응답 헤더에 쿠키 설정 (30일 유지)
    const newResponse = new Response(response.body, response);
    newResponse.headers.append(
      'Set-Cookie',
      `ab_variant=${variant}; Path=/; Max-Age=2592000; SameSite=Lax`
    );
    newResponse.headers.set('X-AB-Variant', variant);

    return newResponse;
  }
};
```

### 2. 엣지에서 JWT 인증 처리 및 요청 필터링

오리진까지 가기 전에 엣지에서 JWT를 검증해 불필요한 요청을 차단한다. DB 조회 없이 서명만 검증하는 패턴이 핵심이다.

```javascript
// Cloudflare Workers - JWT Verification at Edge
import { SignJWT, jwtVerify } from 'jose'; // Workers 환경에서 사용 가능

const PROTECTED_PATHS = ['/api/user', '/api/orders', '/api/admin'];

export default {
  async fetch(request, env) {
    const url = new URL(request.url);

    // 보호된 경로 확인
    const isProtected = PROTECTED_PATHS.some(path =>
      url.pathname.startsWith(path)
    );

    if (!isProtected) {
      return fetch(request); // 엣지 통과, 오리진으로
    }

    const authHeader = request.headers.get('Authorization');
    if (!authHeader?.startsWith('Bearer ')) {
      return new Response(JSON.stringify({ error: 'Unauthorized' }), {
        status: 401,
        headers: { 'Content-Type': 'application/json' }
      });
    }

    const token = authHeader.substring(7);

    try {
      const secret = new TextEncoder().encode(env.JWT_SECRET);
      const { payload } = await jwtVerify(token, secret, {
        issuer: 'https://auth.example.com',
        audience: 'https://api.example.com',
      });

      // 관리자 경로 추가 권한 체크
      if (url.pathname.startsWith('/api/admin') && payload.role !== 'admin') {
        return new Response(JSON.stringify({ error: 'Forbidden' }), {
          status: 403,
          headers: { 'Content-Type': 'application/json' }
        });
      }

      // 검증된 사용자 정보를 헤더로 오리진에 전달
      const modifiedRequest = new Request(request, {
        headers: {
          ...Object.fromEntries(request.headers),
          'X-User-Id': payload.sub,
          'X-User-Role': payload.role,
          'X-Verified-By': 'edge',
        }
      });

      return fetch(modifiedRequest);

    } catch (err) {
      return new Response(JSON.stringify({ error: 'Invalid token' }), {
        status: 401,
        headers: { 'Content-Type': 'application/json' }
      });
    }
  }
};
```

### 3. 동적 콘텐츠 엣지 캐싱 (Stale-While-Revalidate 패턴)

API 응답을 엣지 KV 스토어에 캐싱하고, 만료 시 백그라운드에서 갱신하는 SWR 패턴이다. 사용자는 항상 빠른 응답을 받고, 데이터는 백그라운드에서 최신 상태로 유지된다.

```javascript
// Cloudflare Workers + KV - SWR 캐싱 패턴
const CACHE_TTL = 60;        // 60초 후 stale
const CACHE_SWR = 600;       // 600초 내에는 백그라운드 갱신

export default {
  async fetch(request, env, ctx) {
    const cacheKey = new URL(request.url).pathname;
    const cached = await env.CACHE_KV.getWithMetadata(cacheKey, 'json');

    const now = Date.now();

    if (cached.value) {
      const age = (now - cached.metadata.cachedAt) / 1000;

      if (age < CACHE_TTL) {
        // 신선한 캐시: 즉시 반환
        return jsonResponse(cached.value, { 'X-Cache': 'HIT', 'Age': String(Math.floor(age)) });
      }

      if (age < CACHE_SWR) {
        // Stale이지만 SWR 범위 내: 즉시 반환 + 백그라운드 갱신
        ctx.waitUntil(refreshCache(request, env, cacheKey));
        return jsonResponse(cached.value, { 'X-Cache': 'STALE', 'Age': String(Math.floor(age)) });
      }
    }

    // 캐시 없거나 완전 만료: 오리진 패치 후 저장
    const freshData = await fetchAndCache(request, env, cacheKey);
    return jsonResponse(freshData, { 'X-Cache': 'MISS' });
  }
};

async function fetchAndCache(request, env, cacheKey) {
  const response = await fetch(request.url, {
    headers: { 'X-Internal-Request': 'edge-cache' }
  });
  const data = await response.json();

  await env.CACHE_KV.put(
    cacheKey,
    JSON.stringify(data),
    {
      expirationTtl: CACHE_SWR + 60,
      metadata: { cachedAt: Date.now() }
    }
  );

  return data;
}

async function refreshCache(request, env, cacheKey) {
  try {
    await fetchAndCache(request, env, cacheKey);
  } catch (e) {
    console.error('Background refresh failed:', e);
  }
}

function jsonResponse(data, extraHeaders = {}) {
  return new Response(JSON.stringify(data), {
    headers: {
      'Content-Type': 'application/json',
      'Cache-Control': 'public, max-age=60, stale-while-revalidate=600',
      ...extraHeaders
    }
  });
}
```

## 주의사항 및 트레이드오프

### ⚠️ 런타임 제약

엣지 함수는 전통적인 서버 환경이 아니다. Cloudflare Workers 기준으로 CPU 타임 50ms(유료 플랜 30초), 메모리 128MB, 동기 I/O 불가 등의 제약이 있다. **무거운 연산, 파일 스트리밍, 장시간 실행 작업은 오리진 서버에서 처리**해야 한다.

### ⚠️ 분산 상태 관리의 복잡성

엣지 KV는 Eventually Consistent다. Cloudflare KV의 경우 쓰기 후 읽기 일관성이 전 세계에 전파되는 데 최대 60초가 걸릴 수 있다. **강한 일관성이 필요한 재고 관리, 결제 처리 등은 절대 엣지에서만 처리하면 안 된다.** Durable Objects 같은 강한 일관성 옵션을 사용하거나, 오리진을 Source of Truth로 유지해야 한다.

### ⚠️ 디버깅과 관찰 가능성 한계

로컬 환경과 실제 엣지 환경의 차이, 300개 이상의 PoP에서 분산 실행되는 로그 수집의 어려움은 실무에서 자주 마주치는 고통이다. Cloudflare의 `wrangler tail`, Workers Analytics Engine, 또는 Baselime 같은 엣지 특화 관찰 도구를 초기부터 셋업해두는 것이 필수다.

### ⚠️ 벤더 락인

각 플랫폼의 API(KV, Durable Objects, R2 등)는 플랫폼 종속적이다. 비즈니스 로직은 최대한 **Web Standard API(fetch, Request, Response, crypto)**만 사용해 이식성을 확보하고, 플랫폼 특화 기능은 어댑터 패턴으로 추상화하는 것이 좋다.

### ⚠️ 비용 모델의 차이

요청 수 × 실행 시간으로 과금되는 모델은, 단순 캐시 서빙에도 CPU가 소비되면 비용이 증가한다. 엣지에서 복잡한 연산을 돌릴수록 예상치 못한 비용이 발생할 수 있으니, **Cache API를 적극 활용**해 엣지 함수 실행 자체를 줄이는 전략이 필요하다.

## 정리

엣지 컴퓨팅과 CDN 엣지 함수는 "모든 것을 엣지로" 옮기는 만능 솔루션이 아니다. 올바른 활용 전략은 **어떤 로직을 엣지에 두고, 어떤 로직을 오리진에 남길 것인가**를 명확히 구분하는 것이다.

엣지에 적합한 작업:
- **인증/인가 체크** (JWT 서명 검증, Rate Limiting)
- **지역 기반 라우팅** (A/B 테스트, Feature Flag, Geo-redirect)
- **응답 변환** (헤더 조작, HTML Rewriting, 이미지 최적화)
- **캐싱 레이어** (SWR 패턴, 동적 캐시 무효화)

오리진에 남겨야 할 작업:
- **강한 일관성이 필요한 트랜잭션** (결제, 재고)
- **무거운 비즈니스 로직** (복잡한 DB 조인, 집계 연산)
- **장시간 실행 작업** (배치 처리, 파일 생성)

엣지 함수를 도입할 때는 작은 단위—인증 미들웨어, A/B 테스트, 리다이렉트 처리—부터 시작해 팀의 운영 역량과 관찰 가능성 체계를 먼저 갖추는 것이 현명하다. 기술이 성숙할수록 엣지에서 처리할 수 있는 범위는 점점 넓어질 것이고, 지금 기반을 잘 닦아두는 것이 미래의 아키텍처 경쟁력이 된다.
