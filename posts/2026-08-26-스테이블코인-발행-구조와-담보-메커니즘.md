# 스테이블코인 발행 구조와 담보 메커니즘

## 개요

스테이블코인은 블록체인 생태계에서 가격 안정성을 제공하는 핵심 인프라로, DeFi 프로토콜의 근간을 이루는 요소다. 단순히 "1달러에 고정된 토큰"으로 이해하기 쉽지만, 그 이면에는 복잡한 담보 메커니즘과 경제적 인센티브 설계가 존재한다.

2024년 기준으로 스테이블코인 시장은 약 1,700억 달러 규모를 형성하고 있으며, USDT, USDC, DAI, FRAX 등 다양한 형태의 스테이블코인이 경쟁하고 있다. 백엔드 개발자 관점에서 스테이블코인의 발행 구조를 이해하는 것은 DeFi 프로토콜 개발, 스마트컨트랙트 설계, 그리고 리스크 관리 시스템 구축에 필수적인 지식이다.

이 글에서는 스테이블코인의 담보 유형별 메커니즘을 분석하고, 실제 스마트컨트랙트 코드를 통해 발행 로직을 구체적으로 살펴본다.

## 핵심 개념

### 담보 유형별 분류

스테이블코인은 담보 방식에 따라 크게 세 가지로 분류된다.

| 유형 | 예시 | 담보 | 특징 |
|------|------|------|------|
| 법정화폐 담보 (Fiat-backed) | USDT, USDC | 실제 달러/국채 | 중앙화, 신뢰 필요 |
| 암호화폐 담보 (Crypto-backed) | DAI, LUSD | ETH, WBTC 등 | 탈중앙화, 과담보 필요 |
| 알고리즘 기반 (Algorithmic) | FRAX, UST(실패) | 없거나 부분적 | 자본 효율적, 리스크 높음 |

### 과담보(Over-Collateralization)의 필요성

암호화폐 담보 스테이블코인에서 과담보는 선택이 아닌 필수다. ETH 가격이 변동성이 크기 때문에 1달러의 스테이블코인을 발행하기 위해 150% 이상의 담보물을 요구한다.

```
담보비율(CR) = 담보자산 가치 / 발행된 스테이블코인 가치 × 100%

청산 임계값: CR < 150% → 청산 트리거
안전 CR: 170~200% 권장
```

### CDP(Collateralized Debt Position) 모델

MakerDAO가 선도한 CDP 모델은 암호화폐 담보 스테이블코인의 핵심 아키텍처다.

```
사용자 → 담보 예치 (ETH) → CDP 생성 → DAI 발행
DAI 상환 + 수수료(Stability Fee) → 담보 회수
담보 가치 하락 → 청산자(Liquidator) 개입 → 담보 경매
```

## 실전 예제

### 기본 CDP 스마트컨트랙트 구현

아래는 Solidity로 구현한 단순화된 CDP 기반 스테이블코인 발행 컨트랙트다. 실제 프로덕션 환경에서는 오라클 보안, 재진입 방어, 거버넌스 등 추가 요소가 필요하다.

```solidity
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.20;

import "@openzeppelin/contracts/token/ERC20/ERC20.sol";
import "@openzeppelin/contracts/security/ReentrancyGuard.sol";
import "@openzeppelin/contracts/access/Ownable.sol";

interface IPriceFeed {
    function getLatestPrice() external view returns (uint256 price, uint256 timestamp);
}

/**
 * @title SimpleStablecoin
 * @dev 과담보 방식의 기본 스테이블코인 발행 컨트랙트
 * 담보: ETH, 발행: USD 페깅 스테이블코인
 */
contract SimpleStablecoin is ERC20, ReentrancyGuard, Ownable {
    
    // 상수 정의
    uint256 public constant COLLATERAL_RATIO = 150;    // 150% 최소 담보비율
    uint256 public constant LIQUIDATION_RATIO = 130;   // 130% 청산 임계값
    uint256 public constant LIQUIDATION_BONUS = 110;   // 10% 청산 보너스
    uint256 public constant STABILITY_FEE = 200;       // 2% 연이율 (basis points)
    uint256 public constant PRECISION = 100;
    uint256 public constant BASIS_POINTS = 10000;
    
    IPriceFeed public priceFeed;
    
    struct CDP {
        uint256 collateralAmount;   // ETH 담보량 (wei)
        uint256 debtAmount;         // 발행된 스테이블코인 량
        uint256 lastUpdated;        // 마지막 업데이트 타임스탬프
    }
    
    mapping(address => CDP) public cdps;
    uint256 public totalCollateral;
    uint256 public totalDebt;
    
    event CDPOpened(address indexed owner, uint256 collateral, uint256 debt);
    event CDPClosed(address indexed owner);
    event CollateralAdded(address indexed owner, uint256 amount);
    event DebtRepaid(address indexed owner, uint256 amount);
    event Liquidated(address indexed owner, address indexed liquidator, uint256 debtRepaid);
    
    constructor(address _priceFeed) ERC20("Simple USD", "sUSD") Ownable(msg.sender) {
        priceFeed = IPriceFeed(_priceFeed);
    }
    
    /**
     * @dev ETH를 담보로 예치하고 스테이블코인 발행
     * @param stableAmount 발행할 스테이블코인 수량 (18 decimals)
     */
    function openCDP(uint256 stableAmount) external payable nonReentrant {
        require(msg.value > 0, "Collateral required");
        require(stableAmount > 0, "Debt amount must be positive");
        require(cdps[msg.sender].debtAmount == 0, "CDP already exists");
        
        uint256 ethPrice = _getEthPrice();
        uint256 collateralValueUSD = (msg.value * ethPrice) / 1e18;
        
        // 담보비율 검증
        uint256 requiredCollateral = (stableAmount * COLLATERAL_RATIO) / PRECISION;
        require(collateralValueUSD >= requiredCollateral, "Insufficient collateral ratio");
        
        cdps[msg.sender] = CDP({
            collateralAmount: msg.value,
            debtAmount: stableAmount,
            lastUpdated: block.timestamp
        });
        
        totalCollateral += msg.value;
        totalDebt += stableAmount;
        
        _mint(msg.sender, stableAmount);
        
        emit CDPOpened(msg.sender, msg.value, stableAmount);
    }
    
    /**
     * @dev 부채 상환 후 담보 회수
     * @param repayAmount 상환할 스테이블코인 수량
     */
    function repayAndClose(uint256 repayAmount) external nonReentrant {
        CDP storage cdp = cdps[msg.sender];
        require(cdp.debtAmount > 0, "No active CDP");
        
        uint256 fee = _calculateStabilityFee(msg.sender);
        uint256 totalRequired = cdp.debtAmount + fee;
        require(repayAmount >= totalRequired, "Insufficient repayment");
        
        uint256 collateralToReturn = cdp.collateralAmount;
        totalCollateral -= collateralToReturn;
        totalDebt -= cdp.debtAmount;
        
        _burn(msg.sender, cdp.debtAmount);
        
        delete cdps[msg.sender];
        
        // 수수료는 프로토콜 재무로 (실제로는 거버넌스 토큰 소각 등)
        if (fee > 0) {
            _mint(owner(), fee);
        }
        
        (bool success, ) = msg.sender.call{value: collateralToReturn}("");
        require(success, "ETH transfer failed");
        
        emit CDPClosed(msg.sender);
    }
    
    /**
     * @dev 청산 로직: 담보비율이 청산 임계값 이하일 때 외부 청산자가 호출
     * @param cdpOwner 청산할 CDP 소유자
     */
    function liquidate(address cdpOwner) external nonReentrant {
        CDP storage cdp = cdps[cdpOwner];
        require(cdp.debtAmount > 0, "No active CDP");
        
        uint256 currentRatio = _getCurrentCollateralRatio(cdpOwner);
        require(currentRatio < LIQUIDATION_RATIO, "CDP is healthy");
        
        uint256 debtToRepay = cdp.debtAmount;
        uint256 collateralToSeize = (cdp.collateralAmount * LIQUIDATION_BONUS) / PRECISION;
        
        // 청산자는 부채를 상환하고 담보 + 보너스를 받음
        _burn(msg.sender, debtToRepay);
        
        totalCollateral -= cdp.collateralAmount;
        totalDebt -= debtToRepay;
        
        uint256 remainingCollateral = cdp.collateralAmount - collateralToSeize;
        
        delete cdps[cdpOwner];
        
        // 청산자에게 담보 전송
        (bool success1, ) = msg.sender.call{value: collateralToSeize}("");
        require(success1, "Liquidator transfer failed");
        
        // 남은 담보는 원래 소유자에게 반환
        if (remainingCollateral > 0) {
            (bool success2, ) = cdpOwner.call{value: remainingCollateral}("");
            require(success2, "Owner refund failed");
        }
        
        emit Liquidated(cdpOwner, msg.sender, debtToRepay);
    }
    
    // ============ Internal Functions ============
    
    function _getEthPrice() internal view returns (uint256) {
        (uint256 price, uint256 timestamp) = priceFeed.getLatestPrice();
        require(block.timestamp - timestamp < 3600, "Stale price feed"); // 1시간 유효
        return price;
    }
    
    function _getCurrentCollateralRatio(address owner) internal view returns (uint256) {
        CDP memory cdp = cdps[owner];
        if (cdp.debtAmount == 0) return type(uint256).max;
        
        uint256 ethPrice = _getEthPrice();
        uint256 collateralValueUSD = (cdp.collateralAmount * ethPrice) / 1e18;
        
        return (collateralValueUSD * PRECISION) / cdp.debtAmount;
    }
    
    function _calculateStabilityFee(address owner) internal view returns (uint256) {
        CDP memory cdp = cdps[owner];
        uint256 timeElapsed = block.timestamp - cdp.lastUpdated;
        // 연이율 기반 단순 계산 (실제는 복리 적용)
        return (cdp.debtAmount * STABILITY_FEE * timeElapsed) / (BASIS_POINTS * 365 days);
    }
    
    // ============ View Functions ============
    
    function getCollateralRatio(address owner) external view returns (uint256) {
        return _getCurrentCollateralRatio(owner);
    }
    
    function isLiquidatable(address owner) external view returns (bool) {
        return _getCurrentCollateralRatio(owner) < LIQUIDATION_RATIO;
    }
}
```

### 오프체인 청산 모니터링 서비스 (Java/Spring)

온체인 컨트랙트와 함께, 실무에서는 오프체인에서 CDP 상태를 모니터링하고 청산 기회를 감지하는 백엔드 서비스가 필수다.

```java
@Service
@Slf4j
public class LiquidationMonitorService {

    private final Web3j web3j;
    private final SimpleStablecoin contract;
    private final BigDecimal LIQUIDATION_THRESHOLD = new BigDecimal("130");

    @Scheduled(fixedDelay = 15000) // 15초마다 실행 (블록 생성 주기)
    public void scanForLiquidatableCDPs() {
        log.info("CDP 청산 가능 여부 스캔 시작...");
        
        try {
            // 이벤트 로그로 활성 CDP 소유자 목록 조회
            List<String> activeCDPOwners = fetchActiveCDPOwners();
            
            activeCDPOwners.parallelStream().forEach(owner -> {
                try {
                    BigDecimal ratio = contract.getCollateralRatio(owner).send()
                        .divide(BigDecimal.valueOf(100), 2, RoundingMode.HALF_UP);
                    
                    if (ratio.compareTo(LIQUIDATION_THRESHOLD) < 0) {
                        log.warn("청산 대상 CDP 발견 - Owner: {}, CR: {}%", owner, ratio);
                        triggerLiquidation(owner);
                    }
                } catch (Exception e) {
                    log.error("CDP 조회 실패: {}", owner, e);
                }
            });
        } catch (Exception e) {
            log.error("청산 스캔 실패", e);
        }
    }
    
    private void triggerLiquidation(String cdpOwner) {
        // 청산 트랜잭션 전송 로직
        // 실제로는 MEV 봇과의 경쟁, 가스비 최적화 등 고려 필요
        TransactionReceipt receipt = contract.liquidate(cdpOwner).send();
        log.info("청산 완료 - TxHash: {}", receipt.getTransactionHash());
    }
}
```

## 주의사항 및 트레이드오프

### 1. 오라클 조작 리스크

담보비율 계산은 외부 가격 오라클에 의존한다. 단일 오라클 소스는 플래시론 공격과 결합된 가격 조작에 취약하다.

```
권장 대응:
- Chainlink TWAP (Time-Weighted Average Price) 사용
- 복수 오라클 소스 집계 (Chainlink + Uniswap V3 TWAP)
- 가격 변동 회로 차단기 (Circuit Breaker) 구현
- 스테일 프라이스 감지 (타임스탬프 검증)
```

### 2. 청산 메커니즘의 딜레마

**청산 임계값이 높을수록** → 시스템 안정성 증가, 자본 효율성 감소  
**청산 임계값이 낮을수록** → 자본 효율성 증가, 블랙 스완 이벤트 취약

2020년 3월 "Black Thursday" 사건에서 MakerDAO는 ETH 가격이 50% 급락하면서 오라클 지연과 가스비 급등으로 청산 봇이 작동하지 못해 약 800만 달러의 부실 부채(Bad Debt)가 발생했다.

### 3. 재진입 공격 (Reentrancy Attack)

담보 ETH를 반환하는 `call{value}` 패턴은 재진입 공격의 주요 타깃이다. OpenZeppelin의 `ReentrancyGuard`와 함께 **Checks-Effects-Interactions** 패턴을 반드시 준수해야 한다.

```solidity
// ❌ 위험한 패턴
function withdraw() external {
    uint256 amount = balances[msg.sender];
    (bool success,) = msg.sender.call{value: amount}(""); // 재진입 가능
    balances[msg.sender] = 0; // 상태 업데이트가 늦음
}

// ✅ 안전한 패턴 (CEI)
function withdraw() external nonReentrant {
    uint256 amount = balances[msg.sender];
    balances[msg.sender] = 0;           // 1. Check & Effect 먼저
    (bool success,) = msg.sender.call{value: amount}(""); // 2. Interaction 마지막
    require(success, "Transfer failed");
}
```

### 4. 알고리즘 스테이블코인의 사망 나선 (Death Spiral)

Terra-Luna의 UST 붕괴는 알고리즘 스테이블코인의 근본적 취약점을 보여줬다. 페그 이탈 → 신뢰 하락 → 추가 페그 이탈의 악순환이 발생할 때 이를 막을 최후의 보루가 없다. 순수 알고리즘 모델보다는 FRAX처럼 부분 담보 + 알고리즘 하이브리드 접근이 현실적이다.

### 5. 규제 리스크

USDC의 발행사 Circle은 OFAC 제재 대상 주소의 USDC를 동결한 사례가 있다. 법정화폐 담보 스테이블코인은 본질적으로 중앙화 리스크를 내포하며, 이는 DeFi 프로토콜 설계 시 반드시 고려해야 할 요소다.

## 정리

스테이블코인의 담보 메커니즘은 단순한 토큰 발행 그 이상으로, 경제적 인센티브 설계, 리스크 관리, 오라클 보안이 유기적으로 결합된 복잡한 시스템이다.

| 구분 | 법정화폐 담보 | 암호화폐 담보 | 알고리즘 |
|------|-------------|-------------|---------|
| 자본 효율성 | ★★★★★ | ★★★☆☆ | ★★★★★ |
| 탈중앙화 | ★☆☆☆☆ | ★★★★☆ | ★★★★★ |
| 안정성 | ★★★★★ | ★★★★☆ | ★★☆☆☆ |
| 투명성 | ★★★☆☆ | ★★★★★ | ★★★★★ |

실무 개발자로서 스테이블코인 프로토콜을 구현하거나 연동할 때는 다음 사항을 항상 점검하라:

1. **오라클 보안** - 단일 장애점 제거, TWAP 적용
2. **청산 메커니즘** - 극단적 시장 상황 시뮬레이션 (가스비 급등, 가격 급락)
3. **스마트컨트랙트 감사** - Certik, Trail of Bits 등 전문 감사 필수
4. **서킷 브레이커** - 비상 정지(Emergency Shutdown) 메커니즘 설계
5. **업그레이드 가능성** - 프록시 패턴 적용 여부와 거버넌스 프로세스 정의

스테이블코인 인프라는 DeFi의 근간인 만큼, 코드 한 줄의 버그가 수억 달러의 손실로 이어질 수 있다. 충분한 테스트, 감사, 그리고 점진적 TVL 증가 전략을 통해 안전하게 프로토콜을 성장시켜나가는 것이 중요하다.
